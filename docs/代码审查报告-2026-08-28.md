## 总体结论

项目整体质量**高于一般水平**：更新系统（下载引擎 + 安装管理 + 任务状态机）设计完善，有断点续传、重试、限速、并发、SHA256 校验、备份/回滚；CSP 已配置；`contextIsolation`/`nodeIntegration` 设置正确。

主要风险集中在**更新与启动两条命令行/文件操作链路**上的注入与路径校验缺失。这些问题在「数据源可信（官方更新服务器）」的前提下不易触发，但属于防御性缺口，建议按优先级加固。

## 🔴 高优先级（建议优先修复）

### H1. 命令注入 — `findProcess`（`src/main/game-launcher.js:18`）

```js
execSync(`tasklist /FI "IMAGENAME eq ${exeName}" /FO CSV /NH`, ...)
```

`exeName` 直接字符串拼接进 shell 命令，未转义、未加引号。若游戏 exe 文件名包含 `"`、`&`、`|`、`>` 等 cmd 特殊字符，可被注入执行任意命令。

**修复**：改用参数化调用，避免字符串拼接到 shell 命令：
- 方案 A：`spawn('tasklist', ['/FI', `IMAGENAME eq ${exeName}`, '/FO', 'CSV', '/NH'])`（数组形式不经 shell 解析）
- 方案 B：改用 `wmic process where "name='${exeName}'"` 并对 exeName 做白名单校验（仅允许 `[\w.\- ]+`）

### H2. 路径遍历（Zip Slip / manifest 注入）— 更新安装链路

涉及三处：

1. `src/main/install-manager.js` 的 `backupFiles` / `restoreFiles` / `deleteFiles`：相对路径来自 **zip 条目**（`listZipEntries`）与 **manifest.deleteFiles**，直接 `path.join(installDir, relPath)` 使用，**未校验 `..`**。恶意 zip 含 `../../evil` 或 manifest 的 `deleteFiles: ["../xxx"]`，可读写/删除安装目录之外的任意文件。

2. `src/main/update-task.js` 的 `buildTaskFiles`：`section.fileName`（来自 manifest）直接 `path.join(cacheDir, section.fileName)`，未做 sanitize（对比 `fileNameFromUrl` 有做 `[^a-zA-Z0-9._-] → _` 清洗），manifest 注入可路径遍历。

**修复**：所有进入文件系统的相对路径统一过一道校验：

```js
function safeResolve(base, rel) {
  const resolved = path.resolve(base, rel);
  if (!resolved.startsWith(path.resolve(base) + path.sep)) {
    throw new Error(`Unsafe path rejected: ${rel}`);
  }
  return resolved;
}
```

## 🟡 中优先级

### M1. PowerShell 命令注入面 + 脆弱依赖 — `install-manager.js:113-173`

`listZipEntries` / `extractZip` 用 `spawn('powershell', ['-Command', `...'${path}'...`])`：
- 已做 `'` → `''` 转义，但 PowerShell 命令字符串仍可能因路径含 `` ` ``、`$`、`"` 等被注入；
- 依赖系统 `powershell`（沙箱/受限环境可能被禁用，或触发安全软件 hook）。

**修复**：改用纯 JS zip 库（`yauzl` / `adm-zip` / `extract-zip`），彻底去掉 shell 依赖；或至少对路径做严格白名单校验后用参数文件（`-File`）方式调用。

### M2. 更新源允许 http（明文）— `update-checker.js`

`apiBase`（游戏级或全局 `defaultApiBase`）可为 `http://`。下载文件有 SHA256 校验兜底，但 **manifest 本身、deleteFiles 列表、版本号**均明文传输，可被中间人篡改，进而配合 H2 路径遍历造成更大破坏。

**修复**：强制 `apiBase` 必须 https（启动时校验并警告/拒绝 http），或对 manifest 增加服务端签名校验。

### M3. `combineFiles` 大文件全量读入内存 — `install-manager.js:178`

```js
const data = fs.readFileSync(p); // 每个分片整读进内存
out.write(data);
```

分包合并时整文件读入内存，大型更新包（数百 MB）会 OOM/卡顿。

**修复**：流式拼接 `fs.createReadStream(p).pipe(out, { end: false })`，最后 `out.end()`。

## 🟢 低优先级（建议加固）

### L1. innerHTML 插入未转义数据（CSP 已兜底）— `update-panel.js`

多处把 `game?.name`、`data.version`、`data.mode` 直接插入 `innerHTML` 未转义（如 line 92/119/142/160/232/242-245）。

缓解现状：`index.html` 的 CSP 为 `default-src 'self'`（未含 `unsafe-inline`），inline 事件处理器与 `<script>` 均被 CSP 阻止，实际 XSS 难以执行。

但依赖 CSP 属防御纵深缺口。**建议**与 `settings.js`/`add-game.js` 保持一致，对所有动态数据统一 `escapeHTML()`（这两个文件的转义做得规范）。

### L2. preload 暴露面宽 + `sandbox: false` — `preload.js` / `index.js:24-29`

- preload 暴露了文件扫描、`shell.openPath`、`launchGame`、`updateGame` 等较多能力；
- `webPreferences.sandbox: false`。preload 只用了 `ipcRenderer`/`contextBridge`，**可安全改为 `sandbox: true`**（更小攻击面）；
- `on*` 事件方法未返回 unsubscribe，重复初始化会累积监听器（内存泄漏 + 重复回调）。建议返回移除函数：

```js
onUpdateStatusChange: (cb) => {
  const l = (_e, d) => cb(d);
  ipcRenderer.on('update-status-change', l);
  return () => ipcRenderer.removeListener('update-status-change', l);
}
```

### L3. `tasklist` CSV 解析脆弱 — `game-launcher.js:23`

正则 `/"([^"]+)","(\d+)"/` 解析 CSV，进程名含逗号或输出格式变化时会误判（可能误判游戏退出/运行）。建议按行 split 后 split(',') 取第 2 列，或改用 wmic/PowerShell 结构化输出。

### L4. `spawn('cmd', ['/c', 'start', '', exePath])` — `game-launcher.js:92`

`exePath` 含 `&` 等 cmd 特殊字符时可能被解释（虽数组传参，`/c start` 仍会解析整条命令行）。作者注释说明是为绕过反作弊 CreateProcess 拦截，属合理取舍，但建议对 exePath 做存在性/白名单校验后再启动。

### L5. 代码一致性 — `index.js` 重复 `require('./store')`

line 335/353/404/455/471 多次 `require('./store')`（顶部已解构 store 函数）。node 有模块缓存不影响运行，但应直接使用顶部已导入的函数，保持统一。

## ✅ 做得好的地方

- **更新系统**：`download-engine.js`（断点续传 + 指数退避重试 + 令牌桶限速 + 并发控制 + SHA256/MD5 校验）、`install-manager.js`（时间戳备份 + 失败自动回滚 + 保留最近 3 份）、`update-task.js`（完整状态机 + 暂停/恢复/回滚）质量高，是项目的核心资产。
- **安全配置**：`contextIsolation: true`、`nodeIntegration: false`、CSP `default-src 'self'`。
- **转义规范**：`settings.js`、`add-game.js` 的 `escapeHTML`/`escapeAttr` 使用到位。
- **路径清洗**：`fileNameFromUrl`、`getTaskCacheDir` 对 URL 文件名和版本号做了 `[^a-zA-Z0-9._-] → _` 清洗（H2 中的 `section.fileName` 是漏网之鱼）。
- **hdiff 增量包**：检测到不支持时明确抛错（`applyHdiffIfPresent`），优于静默造成文件不完整。
- **ID 生成**：`crypto.randomUUID()`。
